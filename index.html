Features

Everything a phone-photo scanner should do, on your machine

Two engines in one repo: a free local Python pipeline for bulk scanning, and ready-made configuration for the remote CamScanner MCP endpoint.

No watermark added

The PDFs the local engine writes contain only your pages. No "Scanned with..." footer, no logo, no stamp.

Magic Color filter

A custom OpenCV filter isolates non-uniform shadow fields, estimates the illumination and turns dull gray paper into pure white (#FFFFFF) while keeping vivid ink colours.

Automatic perspective fix

Canny edge detection and contour approximation find the page on a desk or table and warp skewed camera angles flat.

MCP native

Connects Claude Desktop, Kilo CLI, Cursor and any MCP client to the remote Streamable HTTP endpoint at ai-tools.camscanner.com/mcp.

Fast and offline

Runs on your own CPU with no cloud round trip. The README reports about 3.2 seconds for 20 high-resolution pages.

Multi-page batch to one PDF

Reads JPG, PNG or WebP photos from a folder, orders them by filename and bundles them into a single 300 DPI PDF.

How it works

Five stages from crooked photo to flat white page

Every number below comes straight from scripts/batch_scanner.py. For the full derivations see the Algorithm Deep Dive.

The Magic Color tone curve

A 256-entry lookup table. Ink below 40 scales by 0.75, 40 to 215 stretches onto 30 to 255, and anything 215 or brighter becomes pure white.

Why shadows disappear

Paper brightness is lighting times reflectance. Divide by an estimate of the lighting and the shadow cancels.

The sharpening kernel

A 3x3 unsharp filter applied last. The weights sum to 1.0, so overall brightness does not shift; only edges get crisper.

The MCP angle

Let your AI agent call the scanner

The README describes the CamScanner MCP as an official remote Model Context Protocol endpoint over Streamable HTTP. It lets agents like Claude and Kilo trigger OCR, PDF merging, document translation and format conversion through tool calls. This repo shows how to wire it up, and keeps a free local engine beside it.

Quick start

From clone to PDF in two commands

Commands are copied from the README. You need Python 3.9 or newer.

1Install

terminal
# Clone the repository
git clone https://github.com/MHJoy99/camscanner-mcp-hd-scanner.git
cd camscanner-mcp-hd-scanner

# Install Python requirements
pip install opencv-python pillow numpy pypdf

# (Optional) Install official CamScanner CLI
npm install -g camscanner-cli

2Scan a folder of photos

terminal
python scripts/batch_scanner.py "path/to/raw_photos" "output/Scanned_Document_HD.pdf"
  1. Finds the page contour and removes the table edges.
  2. Estimates ambient light and eliminates shadows.
  3. Applies the Magic Color tone curve.
  4. Sharpens with an unsharp kernel.
  5. Exports a 300 DPI multi-page PDF with no watermark.

Good to know. Pass both arguments to batch_scanner.py. A lighter script, scan_to_pdf.py, processes the images sitting next to it and writes Scanned_HD_Output.pdf; run it as python scan_to_pdf.py bw for a black-and-white filter (default is magic_color). Both are read from the repo's code, not the README.

FAQ

Questions people ask

Answers are taken from the README, the docs folder and the code.

What is CamScanner MCP & HD Auto-Scanner?

It is an open-source (MIT) Python project with two engines. A local OpenCV pipeline turns phone photos of paper into clean multi-page PDFs: it finds the page, flattens the perspective, estimates and removes shadows, whitens the paper and sharpens the ink. The repo also documents how to connect AI agents such as Claude Desktop, Kilo CLI and Cursor to the CamScanner MCP endpoint. It is an independent project and is not affiliated with CamScanner or INTSIG.

How do I scan phone photos to a PDF without a watermark?

Put your photos in a folder (JPG, PNG or WebP; the script also reads JPEG and BMP) and run python scripts/batch_scanner.py "path/to/raw_photos" "output/Scanned_Document_HD.pdf". The script processes the images in filename order, applies the Magic Color pipeline to each one and writes a single multi-page PDF. The local engine adds no stamp or watermark to the PDF it writes.

Does it work offline? Are my documents uploaded?

The local engine runs entirely on your machine with OpenCV, NumPy and Pillow, and its code makes no network calls, so your photos are not uploaded. The remote CamScanner MCP endpoint is different: the integration guide notes that it needs internet access and a sign-in, and that documents sent to it travel to CamScanner's cloud.

How does the shadow removal and paper whitening work?

It estimates the lighting first: a grayscale copy is dilated with an 11x11 kernel, which erases thin ink strokes, then smoothed with a 31x31 median filter. Each colour channel is then multiplied by 255 divided by that background estimate, which cancels uneven light and cast shadows. A tone curve maps values of 215 and above to pure white and deepens dark ink, and a 3x3 sharpening kernel finishes the page.

How do I connect it to Claude Desktop, Cursor or Kilo CLI?

Add the CamScanner MCP endpoint, https://ai-tools.camscanner.com/mcp, to your client's MCP configuration. The README shows a Kilo CLI snippet (type remote, with an X-IS-AGENT: general header) and a Claude Desktop snippet. The MCP Integration Guide in the repo also covers Cursor and VS Code, the OAuth 2.0 sign-in and the camscanner-cli commands.

What can the CamScanner MCP endpoint do?

According to the README it is a remote Model Context Protocol endpoint using Streamable HTTP that lets AI agents trigger OCR, PDF merging, document translation and format conversion through tool calls. The integration guide also lists table extraction and document search. These tools run on CamScanner's servers, not in this repo's Python engine.

Is there a page or resolution limit?

The README states there is no page cap and that the PDF is written at 300 DPI. In the code, every image found in the folder is processed and held in memory, then saved as one PDF with JPEG quality 95 and 300 DPI metadata, so very large batches are bounded by your available memory rather than by a built-in limit.

How fast is it?

The README reports about 3.2 seconds for 20 high-resolution pages on a CPU, and the Algorithm Deep Dive reports about 153 ms for one 12-megapixel page on its test machine. These are the author's own figures and will vary with your hardware.

Which situations does it handle poorly?

Page detection looks for a four-corner outline covering at least 40% of the frame. If it finds a different outline it falls back to a bounding box, and if it finds none it trims a 2.5% border. White paper on a white desk is hard for edge detection, and the scripts do not flatten curved book pages or correct glossy reflections, because a plain perspective warp assumes a flat sheet.

Is it affiliated with CamScanner? What licence is it under?

No. This is an independent project by MHJoy99 and is not affiliated with CamScanner or INTSIG. The README calls its filter "CamScanner Magic Color"; the repo reproduces a similar look with OpenCV, and CamScanner remains a trademark of its owner. The code is MIT licensed, free for personal, educational and commercial use.
